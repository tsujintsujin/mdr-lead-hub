# 02 · n8n and its 9 workflows

**Connects to:** everything. n8n is the hub (see
[00-how-it-all-connects.md](00-how-it-all-connects.md)). It also runs the two
helpers that have no guide of their own: **Lighthouse** (speed test) and the
**ProPublica IRS lookup**, both covered here.

---

## 1. What it is

n8n is an automation tool, like Zapier, but installed on this PC. A
**workflow** is a chain of **nodes**: a trigger (a web address being called,
or a clock), then steps (call an API, run some JavaScript, branch on a
condition).

This project's n8n is **not** inside MDRLeadHub. It's your shared n8n:

| | |
|---|---|
| Program and start script | `D:\AIO Freelance\n8n\start_n8n.cmd` |
| Its data (workflows, credentials, run history) | `D:\AIO Freelance\n8n\.n8n\` (`database.sqlite`) |
| Its own settings | `D:\AIO Freelance\n8n\.env` (loaded by the start script) |
| Address | http://localhost:5678 |
| Login | Your n8n account (Chrome remembers it) |
| Other workflows in the same n8n | TheJobStash, Portfolio, YouTube, etc. The MDR ones all start with **"MDR · "** |
| The MDR workflows' source code | `MDRLeadHub/n8n/` |
| API key used by the build script | `D:\AIO Freelance\Credentials\n8n\api-key.txt` |

**The workflows are built from code.** `n8n/build.mjs` writes every workflow
and uploads it through n8n's API. If you change a workflow by clicking in the
editor, the next `node n8n/build.mjs` overwrites it. Use the editor to *look
and learn*; change things in the code.

## 4. Each workflow in detail

Each block below lists the nodes in the order they run, with their real names
as they appear in the editor.

### 4.1 MDR · Lead intake — the main one

**Trigger:** `POST /webhook/mdr-intake` (from WordPress). **Active.**

| # | Node | What it does |
|---|---|---|
| 1 | WordPress form in | Receives the submission |
| 2 | Check signature → Signed by WordPress? | Recomputes the HMAC; if wrong → **Reply 401** and stop. If right → **Reply 202** straight away (so WordPress isn't kept waiting) and carry on |
| 3 | Tidy the submission | Cleans fields, works out the Source (Google Ads, Organic search, ...) from the tracking |
| 4 | CRM: seen them before? | `GET /api/lookup?email=&website=`: same people recently? |
| 5 | Open their website | Downloads their home page; reads title, description, H1, mobile viewport, local-business schema, booking link or phone link, https, platform |
| 6 | Lighthouse address → Lighthouse (mobile, on this PC) | Runs `node tools/lh.mjs <address>` (see section 6) |
| 7 | Nonprofit form? → IRS lookup (ProPublica) | Site B only: searches IRS records by name and state |
| 8 | Score the website | Turns all that into the checkup the visitor sees |
| 9 | WordPress: show results | Sends stage `audit` to the visitor's results page |
| 10 | Rules first | Fixed rules, up to 70 points (section 5) |
| 11 | Worth asking the AI? | Skips the AI for spam |
| 12 | CRM: past corrections | `GET /api/examples?limit=5`: verdicts people changed |
| 13 | Write the prompt → Ollama qwen2.5:7b | Asks the model (see [04-ollama.md](04-ollama.md)) |
| 14 | Decide the verdict | Combines rules + AI into score, verdict, segment, reasons |
| 15 | Sheet: team roster | Reads the Team tab |
| 16 | CRM: open leads per rep | `GET /api/workload` |
| 17 | Pick the rep | The least busy rep who covers that segment |
| 18 | CRM: save the lead | `POST /api/leads` → gets an ID like `MDR-1008` |
| 19 | Write Slack, Asana and email | Builds every message |
| 20 | Real lead? | Spam skips Slack and Asana |
| 21 | Slack: post to the rep's channel | The lead card with buttons |
| 22 | Needs an Asana task? → Asana: create follow-up task → Asana: put it in the right column | Only **Hot** (due in 24 h) and **Needs a conversation** (due in 48 h). Warm and Not a fit get no task |
| 23 | Emails to send → Brevo: send email | **Disabled** |
| 24 | Gather the links → CRM: add Slack and Asana links | Saves the Slack message and Asana task on the CRM lead |
| 25 | Sheet row → Sheet: log the lead | Adds or updates the row (matched on **Lead ID**) |
| 26 | Tell the visitor who's calling → WordPress: name the strategist | Sends stage `routed` to the results page |

The editor shows coloured sticky notes over the canvas (Receive, Look up,
Score, Route, Tell everyone) that group these steps.

### 4.2 MDR · Sync a change everywhere

**Trigger:** `POST /webhook/mdr-crm-event`, called by the CRM and by the Slack
and Asana workflows. Needs header `X-MDR-Key`. **Active.**

Check the CRM key → Trusted caller? → Reply 200 → CRM: load the lead → Sheet:
team roster → **Plan the updates** (works out everything that must change) →

- Slack message to update? → Slack: refresh the lead message (`chat.update`,
  the buttons change too) → Slack: note it in the thread
- Asana changes? → Asana steps → Asana: apply (move column, complete, reassign)
- Won? Start onboarding → Asana: create onboarding project → Onboarding tasks →
  Asana: add onboarding task (6 tasks, each with a due date)
- Sheet update → Sheet: update the row
- Emails to send → Brevo: send email (**disabled**)
- What happened → CRM: log it on the timeline

Actions it handles: `stage` (new, contacted, booked, won, lost), `override`
(verdict corrected), `reassign`.

### 4.3 MDR · Slack buttons

**Trigger:** `POST /webhook/mdr-slack`, reached from the internet through the
tunnel. **Active.**

Slack button clicked → Check it came from Slack (signing secret, 5 minutes) →
Signed by Slack? → **Ack within 3 seconds** (Slack shows an error if it waits
longer) → A button that changes something? → Slack: who clicked? → CRM: load the
lead → Work out the change → CRM: save it → Sync everywhere else.

| Button | `action_id` | Change |
|---|---|---|
| Mark contacted | `mdr_contacted` | Stage → Contacted |
| Booked a call | `mdr_booked` | Stage → Booked |
| Not a fit | `mdr_not_fit` | Verdict → Not a fit (saved as a correction the AI learns from) |
| Open in CRM | `mdr_open` | Just a link; n8n ignores it |

### 4.4 MDR · Asana updates

**Trigger:** `POST /webhook/mdr-asana`, through the tunnel. **Active.**

Asana event → Handshake or verify → Handshake? → (first time) Echo the secret,
(every time after) Ack → Task changes we care about → Asana: is it done? → CRM:
which lead? → Work out the change → CRM: save it → Sync everywhere else.

Ticking the task done, or dragging it to **Contacted** or **Booked**, moves the
lead forward. It never moves a lead backwards.

### 4.5 MDR · Follow-up watch

**Triggers:** every hour, and `GET /webhook/mdr-followup-now?hours=...`.
**Active.**

How long is too long (24 h, or `?hours=`) → CRM: leads nobody has called
(`/api/leads?stale_hours=24`: Hot, Warm or Needs a conversation, still New, no
first contact) → Sheet: team roster → One alert per lead (skips leads already
escalated) → Slack: flag it in #mdr-ops → Slack: nudge the lead thread → Brevo:
email the manager (**disabled**) → CRM: mark it escalated.

### 4.6 MDR · Daily digest

**Triggers:** every day at 8:00 New York time, and
`GET /webhook/mdr-digest-now`. **Active.**

CRM: the last 24 hours (`/api/stats`) → CRM: still waiting → Sheet: team roster
→ Write the digest → Slack: post to #mdr-daily → Brevo: email the manager
(**disabled**).

### 4.7 MDR · Roster

**Trigger:** `GET /webhook/mdr-roster` with header `X-MDR-Key`. **Active.**
The CRM's Team page calls it. Check the CRM key → Sheet: team roster → Shape the
roster → Send it back.

### 4.8 MDR · Sheet helper

**Trigger:** `POST /webhook/mdr-sheet-helper` with the key. **Active.** Lets
`tools/reset-demo.mjs` clear the Leads tab using n8n's Google login. It refuses
any spreadsheet except this one.

### 4.9 MDR · Error alerts

**Trigger:** any other MDR workflow failing (n8n's Error Trigger). It posts the
failed workflow, node and error to `#mdr-ops`.

`build.mjs` sets it as the **error workflow** of the other eight (in each
workflow: **⋯ menu → Settings → Error workflow**). But it is **switched off
right now**, and it has **never run**: when Follow-up watch and Daily digest
failed on 3 and 4 Nov 2026, no alert was posted. Switch it on with the toggle at
the top of the editor to get alerts. Running `node n8n/build.mjs` again
deactivates and re-uploads every workflow, so check the toggle after a build.

## 5. The scoring, exactly (from `n8n/lib/intake.js`)

### Spam first (score 0, routed to nobody)

- Throwaway email domain (mailinator, yopmail, 10minutemail, ...)
- Message with sales words (backlinks, guest post, casino, crypto, link
  building, ...) or more than one link
- Business name and contact name both look like keyboard mashing
- The AI says they are selling **to** MDR

### Rules, up to 70 points

**Site A (clinics):**

| Item | Points |
|---|---|
| ZIP in Northeast Ohio (440–449) / rest of Ohio (430–458) / elsewhere or none | 20 / 12 / 5 |
| Budget over $5,000 / $1,500–5,000 / $500–1,500 / not sure / under $500 | 20 / 17 / 11 / 6 / 2 |
| Timeline ASAP / next 3 months / just looking | 15 / 9 / 3 |
| Website problems MDR could fix (slow speed, 2+ missing basics, no booking button) | up to 15 |
| Under $500 **and** just looking | forced **Not a fit** |

**Site B (nonprofits):**

| Item | Points |
|---|---|
| 501(c)(3) yes / applied / not sure / no | 25 / 10 / 8 / 0 |
| Found in IRS records (or says yes but no match) | 15 (or 5) |
| No Ad Grants yet / has it but barely uses it / runs it well | 12 / 15 / 5 |
| Staff 26+ or 6–25 / 1–5 / volunteers only | 10 / 7 / 3 |
| Website loads on https | 5 |
| Hospital, school or government, or no 501(c)(3) | forced **Not a fit** |

### The AI, up to 30 points

The model returns `intent` (0–30), `confidence` (0–1), `segment`, a summary,
reasons, an opening line and red flags.

### The verdict

1. Spam → **Spam**.
2. AI didn't answer → **Needs a conversation** (rules score only).
3. A rule forced it → **Not a fit**.
4. Clinic form but the AI is fairly sure (≥ 0.5) it's another kind of business
   → **Needs a conversation**, routed to that segment's rep.
5. AI confidence under 0.55 → **Needs a conversation**.
6. Otherwise, total = rules + AI: **70+ Hot**, **45–69 Warm**, **30–44 Needs a
   conversation**, **under 30 Not a fit**.

### Routing

From the Team tab (see [05-google-sheet.md](05-google-sheet.md)): reps whose
**Covers** includes the segment → if none, reps covering `other` → if none, the
manager (`*`). Among them, the one with the fewest open leads (New, Contacted,
Booked). Ties go to whoever is higher in the sheet.

## 6. Lighthouse and the IRS lookup

**Lighthouse** is Google's speed test. `tools/lh.mjs` starts a hidden Chrome
on this PC, loads the visitor's site as a phone would, and prints one line:
`{"ok":true,"score":41,"lcp_s":6.2,"final_url":"..."}`. It gives up after 55
seconds. The address arrives base64-encoded so nothing the visitor typed can
reach the command line. If it fails, the speed shows "not measured"; there is
no made-up number. Run it yourself:
`node tools/lh.mjs $(node -e "console.log(Buffer.from('https://example.com').toString('base64url'))")`

**ProPublica** keeps a free copy of IRS nonprofit records. The **IRS lookup
(ProPublica)** node:

- if the visitor typed a 9-digit EIN, fetches
  `https://projects.propublica.org/nonprofits/api/v2/organizations/<EIN>.json`;
- otherwise searches `.../api/v2/search.json?q=<name>&state[id]=<state>` and
  keeps an exact or close name match (ignoring words like Inc, The, Foundation).

It keeps the name, city, state and EIN. If nothing matches, the lead loses the
15 "found in IRS records" points.
Try it: https://projects.propublica.org/nonprofits/search?q=Cleveland+Animal+Protective+League

## 7. Changing a workflow the right way

1. Edit `n8n/build.mjs` (the nodes and their wiring) or `n8n/lib/intake.js`
   (scoring and routing) or `n8n/lib/messages.js` (Slack, Asana and email text).
2. `node n8n/test.js`: checks scoring, routing and messages without sending
   anything. Must say all passed.
3. `node n8n/build.mjs`: uploads and re-activates every MDR workflow.
   `node n8n/build.mjs --dry` only writes the files in `n8n/workflows/` (secrets
   masked) so you can read them.
4. Submit a test lead and open the execution.

## 8. Reading a run (the best way to learn)

1. Open http://localhost:5678/home/executions.
2. Click a run of **MDR · Lead intake**.
3. Click any node: the left panel shows what came in, the right what went out.
4. A red node is where it failed; its error message is on the right.

## 9. When something is wrong

| Symptom | Where to look |
|---|---|
| Nothing reaches the CRM after a form | Executions of **MDR · Lead intake**. No run at all → n8n was down (check the WordPress Intake screen). A red run → the red node says why |
| Follow-up watch / digest failing | Usually "The service refused the connection": the CRM was off |
| Slack button does nothing | Executions of **MDR · Slack buttons**. No run → the tunnel is off |
| A change I made in the editor disappeared | `build.mjs` was run again; put the change in the code |
| `Cannot GET /home/workflows` | n8n was still starting; wait a few seconds and reload |
